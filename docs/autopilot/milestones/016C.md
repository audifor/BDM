# Milestone 016C - Real players in MatchViewer

## Goal

Make the existing MatchViewer visually represent the ten real starters already present in `MatchSimulation.lineups`, and resolve sporting-event PlayerIds to player names.

This is a UI/application integration milestone. Do not change basketball outcomes.

## Required behavior

### Court tokens
- Replace the five generic home tokens and five generic away tokens with the real Players from `simulation.lineups`.
- Resolve each PlayerId through the current GameWorld.
- Show at least:
  - last name
  - primary position
- Keep exactly five tokens per side.
- Use static UI coordinates based on the player's primary position. Do not add coordinates or movement to Domain/Engine.
- Keep the existing schematic court and playback behavior.

### Event feed
For sporting events resolve `event.playerId` from GameWorld.
Use concise text such as:
- `08:42 Mercer scores 2 for Ironhollow Vipers`
- `08:21 Novak misses`
- `07:58 Vega turnover`

Do not duplicate names into MatchEvent. PlayerId remains the source link.

Structural events remain team/period oriented.

### Safety
- If a PlayerId cannot be resolved, fail visibly/explicitly rather than inventing a name.
- Do not silently substitute roster players.
- MatchViewer must not select starters. It consumes `simulation.lineups`.

### Keep unchanged
- pause
- x1/x2/x4/x8
- skip to end
- continue
- result application exactly once
- event reveal timing
- MatchEngine
- TeamStrength
- SQUAD
- no player boxscore yet

## Tests

Use existing testing infrastructure only. Do not add React Testing Library if it is not already installed.

Prefer pure helper/selector tests if useful:
- resolving a lineup returns exactly the five expected Players
- event PlayerId resolves to expected Player
- ordering/position mapping is deterministic

Existing Application/Viewer/store tests must remain green.
