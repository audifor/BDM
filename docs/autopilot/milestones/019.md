# Milestone 019 - Fouls and free throws v1

## Goal

Add a deliberately minimal foul/free-throw layer to the possession engine, enough to remove the abstract one-point scoring possession as the primary way to create one-point scores and to produce explicit free-throw events.

This is the final autonomous milestone in the tranche. Do not continue into rotations/fatigue.

## Prototype scope

Implement shooting-foul/free-throw behavior only if it can be done cleanly within the current possession architecture.

Do NOT attempt full FIBA/NBA/NCAA foul-rule modeling.

Centralize provisional constants near MatchEngine and document that CompetitionRules will replace them later.

## Events

Introduce explicit sporting events as needed, preferably:
- `foul`
  - teamId of committing team
  - playerId of committing defender
  - foulType limited to a small v1 vocabulary, e.g. `shooting`
- `freeThrowMade`
  - teamId
  - playerId shooter
- `freeThrowMissed`
  - teamId
  - playerId shooter

All events retain sequence/period/clock/cumulative score semantics.

Do not invent names inside events.

## Player attribution

- shooter must be from attacking lineup
- fouling defender must be from defending lineup
- use actor/detail RNG for attribution
- sporting RNG decides whether a sporting foul/FT outcome occurs
- player ratings do not yet control foul rate or FT percentage unless doing so requires no new product rule. Prefer a simple prototype constant.

## Free throws

Use explicit free throws rather than fabricating a `shotMade points: 1` field-goal event.

For the v1 shooting-foul path:
- support a simple 2-FT case
- 3-FT support is optional only if the existing shot/outcome model exposes a clean 3-point-attempt distinction before the foul decision
- no and-one required
- each FT has its own made/missed event
- made FT increments score by exactly 1
- missed FT does not

After the final FT, normal possession transition resumes.

If the final FT is missed and the current rebound architecture can cleanly handle it, produce a rebound. If doing this would force a large engine redesign, keep FT rebounds explicitly deferred and document the simplification.

## Legacy made1

Remove or deprecate the abstract `made1` possession outcome from productive simulation if explicit free throws now cover one-point scoring.

Do not preserve obsolete behavior merely for old tests. Update tests to the new explicit model.

## Team-foul bonus

Do NOT implement full bonus rules unless the current architecture makes it trivial. The canonical requirement for this milestone is explicit shooting fouls + explicit free throws.

If bonus rules require decisions about FIBA-like vs NBA-like semantics, return them as deferred CompetitionRules rather than choosing silently.

## Boxscore

Extend derived player stats minimally with:
- freeThrowsMade
- freeThrowsAttempted
- foulsCommitted

Points already derive from scoring events and must include made free throws.

If `fieldGoalsMade/Attempted` currently count `shotMade`, ensure free throws do not count as field goals.

Viewer stats panel may show FT and PF only if space remains readable. Do not redesign the whole Viewer.

## Tests

Add focused controlled tests for:
- foul event defender belongs to defending lineup
- FT shooter belongs to attacking lineup
- made FT adds exactly 1
- missed FT adds 0
- two-FT sequence produces 0, 1 or 2 points according to outcomes
- FT does not increment FGM/FGA
- FTM/FTA reconstruct from events
- foulsCommitted reconstruct from events
- finalScore reconstructs from all scoring events including FT
- same seeds deterministic
- no sporting-result dependence on actor attribution RNG
- no productive abstract made1 path remains if replaced

Preserve overtime, clock non-negativity, period-end behavior and result application.

## Architecture and stop rule

Update `docs/ARCHITECTURE.md` with all prototype simplifications and explicitly defer universal foul/bonus rules to CompetitionRules.

If clean implementation requires choosing incompatible FIBA/NBA/NCAA rules or rewriting large portions of MatchEngine, return BLOCKED instead of making a product decision.

## Do not implement

- foul-out/disqualification
- individual foul limits
- bonus/one-and-one unless trivial and unambiguous
- technical/flagrant/unsportsmanlike fouls
- substitutions
- rotations
- fatigue
- injuries
- tactics
