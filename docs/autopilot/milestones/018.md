# Milestone 018 - Rebounds and assists v1

## Goal

Make missed shots produce explicit rebound events and allow made field goals to carry a derived assist attribution, while preserving deterministic simulation architecture.

This milestone may legitimately change match results because offensive rebounds alter possession flow. Keep the model intentionally simple.

## Rebound event

Add a sporting MatchEvent for rebounds with:
- type: `rebound`
- teamId
- playerId
- reboundType: `offensive` | `defensive`
- period/clock/sequence/cumulative score consistent with the event system

A miss must be followed by exactly one rebound event before the next possession is resolved.

### Rebound outcome
Use the SPORTING RNG to decide offensive vs defensive rebound because this changes possession flow.

Use a simple prototype offensive-rebound probability, centralized as a MatchEngine config/constant, roughly basketball-plausible. Do not claim it as final CompetitionRules.

- defensive rebound -> possession changes team
- offensive rebound -> same attacking team keeps possession

Do not create impossible infinite same-clock loops. Time must continue to progress according to the existing possession model.

### Rebound actor
Choose the rebounder from the appropriate team's current five-player lineup using the actor/detail RNG, not the sporting RNG.
Uniform selection is acceptable in v1.
Do not use Player ratings for rebound selection yet.

## Assists

For made 2-point and 3-point field goals, allow an optional:
`assistPlayerId?: PlayerId`

on `shotMade`.

Rules:
- assister must be from the scoring team's lineup
- assister cannot equal the scorer
- a 1-point event/free-throw-like legacy score, if still present, must not receive an assist
- whether a made field goal is assisted is attribution/detail and must not alter score or possession outcome
- use the actor/detail RNG stream, not the sporting RNG, so changing assist attribution cannot alter the sporting result

Use one simple prototype assist probability. No playmaking weighting yet.

## Boxscore extension

Extend derived PlayerMatchStats with:
- offensiveRebounds
- defensiveRebounds
- rebounds
- assists

`rebounds = offensiveRebounds + defensiveRebounds`.

Keep all stats derived from events.

Update Viewer stats panel with compact REB and AST columns if practical without a redesign.

## Determinism and RNG isolation

Add tests that:
- every miss has a subsequent rebound event
- offensive rebound retains possession
- defensive rebound changes possession
- rebounder belongs to correct lineup
- assister belongs to scorer's lineup and differs from scorer
- changing actor/detail RNG does not alter score/outcome stream except attribution/detail fields
- same complete seeds reproduce exact events
- boxscore rebound/assist totals reconstruct from events

If the current engine structure makes "change possession" difficult to assert directly, test the next attacking team or an equivalent observable event.

## Keep out of scope

- rating-weighted rebounding
- playmaking-weighted assists
- steals
- blocks
- fouls
- free throws
- substitutions
- fatigue
- player minutes
- persisted stats

## Documentation

Update architecture with:
- rebounds now explicit
- offensive rebounds may extend possessions
- assist attribution is optional on made field goals
- sporting RNG vs attribution RNG responsibilities
- rebound/assist stats remain derived

## Stop condition

If implementing offensive rebounds requires a broad rewrite of the possession engine rather than a focused evolution, return BLOCKED with the architectural reason instead of improvising a large redesign.
