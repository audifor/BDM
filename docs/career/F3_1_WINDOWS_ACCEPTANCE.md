## Manual procedure

Use a Windows machine with the Tauri executable and the same repository revision (`a214d68a` plus the F3.1 documentation commit).

### Configuration

- Universe: ACB test career.
- Club: UCAM Murcia (`userTeamKey: 'ucm'`).
- Coach: the F2/F3 deterministic profile (`Elena Piloto`) or an equivalent valid user-created identity.
- Seed: retain the production test seed; do not edit generated entities.
- Save checkpoint: after the first user game and again on day 15.

### Walkthrough

1. Start a new career and complete coach identity creation.
2. Verify the F1 arrival briefing shows the real UCAM club, Board, staff, responsibilities and next fixture.
3. Open Home and verify the Director Hub is compact, legible and not a second Inbox.
4. Confirm an autonomous staff item or real human situation appears only when its canonical source exists.
5. Accept one executable staff/HRPG action and verify the action notice appears.
6. Open Staff and verify the corresponding responsibility, reaction, relationship or memory from canonical data.
7. Open Coach and verify the relationship/history view reads the same data.
8. Open Training, Tactics and Match; verify the existing navigation and no nested scroll trap.
9. Continue through the next match and return to Home.
10. Save, close and load. Confirm consumed meeting/recommendation actions do not reappear and memories remain.
11. Continue to day 30 and verify training, fatigue/cohesion, scouting, match result and Home context remain coherent.

### Evidence to capture

- One screenshot per: identity, F1 briefing, Home Hub, Staff relationship/memory, Coach history, Training/Tactics, Match, post-match Home and loaded Save V4.
- The save identifier and current date at day 15 and day 30.
- For every action: source label, button text, resulting visible state and whether it disappears or remains pending after reload.

### PASS/FAIL criteria

PASS requires all screens to be readable at the target resolution, no duplicate Inbox, no decorative/mock human event, valid action navigation, correct empty/expired states and Save V4 continuity. Any invented event, repeated consumed action, broken navigation, unreadable layout or lost memory is FAIL.
